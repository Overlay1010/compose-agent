# 에이전트 평가

정답 있는 명령 30개로 "에이전트가 도구를 맞게 고르고 인자를 맞게 채우는지"를, 이어지는 대화 · 스스로 고치기 9개로 "앞 대화를 기억하고 오류를 스스로 수습하는지"를 잰다.

```powershell
cd backend
compose_venv\Scripts\python -m eval.run                                  # .env의 모델 (지금 gpt-6-luna)
compose_venv\Scripts\python -m eval.run --models gpt-6-luna,gpt-5.4-mini # 모델 비교
```

- 명령과 정답: [backend/eval/cases.py](../backend/eval/cases.py) · 채점: [backend/eval/spec.py](../backend/eval/spec.py)
- 결과 원본(명령마다 부른 도구 · 인자 · 답 · 시간 · 토큰): `backend/eval/results/`
- 실제 API를 부르므로 비용이 든다. 명령 하나에 입력 토큰 약 5,500~5,900개(대부분 도구 설명과 규칙), 출력 70~80개.

## 명령 30개

| 분야 | 개수 | 예 |
| --- | --- | --- |
| 조옮김 · 옥타브 | 7 | "베이스 2키 올려줘", "2마디부터 4마디까지 베이스 한 옥타브 올려줘" |
| 퀀타이즈 | 5 | "코드 박자 정리해줘, 너무 딱딱하진 않게", "베이스 박자를 50%만 당겨줘" |
| 세기 | 6 | "하이햇 좀 약하게", "9마디부터 패드 약하게", "베이스 볼륨 20 줄여줘" |
| 스윙 | 4 | "하이햇에 살짝 스윙 넣어줘", "16분음표 스윙 60%로" |
| 여러 도구 | 3 | "하이햇 좀 약하게 하고 살짝 스윙 넣어줘" |
| 편집하면 안 됨 | 5 | "좀 더 좋게 해줘"(막연함), "드럼 2키 올려줘"(드럼은 조옮김 대상 아님), "스트링 트랙 올려줘"(없는 트랙) |

## 채점

- 실제로 음을 바꾼 편집만 본다 (정보 조회 · 실패한 호출 · 바뀐 음 0개는 제외). **시키지 않은 편집을 더 하면 오답.**
- 정도를 말하는 명령은 범위로 채점: "좀 약하게" = 0.5~0.85배 또는 −8~−40, "살짝 스윙" = 53~60%, "너무 딱딱하지 않게" = 강도 0.5~0.85
- 같은 결과를 내는 다른 방법도 정답: 한 옥타브 = `shift_octave ±1` 또는 `transpose ±12`, 세기 = 곱하기 또는 더하기
- 하이햇은 42(닫힘) · 44(페달) · 46(열림) 안에서 고르되 42는 꼭 포함
- 정답 30개가 실제 도구로 만들 수 있는 답인지도 테스트로 확인한다 (`tests/test_eval.py`): 정답 호출을 그대로 실행하면 음이 바뀌고 정답으로 채점돼야 한다

3회차 기준: 응답 시간 중앙값 gpt-6-luna 3.1초 · gpt-5.4-mini 2.2초, LLM 호출 평균 약 2회(도구 한 번 + 답).

### 배운 것

- **1회차의 3개 실패는 모델이 아니라 우리 코드 문제였다.** 일부 모델은 도구를 쓰려면 `reasoning_effort='none'`이 필요해서 오류가 나면 자동으로 바꿔 다시 부르게 해 두었는데, 명령 4개를 동시에 보내면 먼저 실패한 요청이 설정을 바꿔 놓는 바람에 나머지는 "이미 바뀌었다"고 보고 재시도 없이 실패했다. 이번 요청이 실제로 보낸 값으로 판단하도록 고치고 테스트로 고정했다. 서버에 여러 사람이 동시에 요청할 때도 같은 문제가 날 뻔했다.
- **"스트링 트랙 올려줘"(없는 트랙)**: 처음엔 Pad를 "스트링 역할"이라 짐작해 편집했다. 규칙을 넣은 뒤 2회차엔 맞았지만 3회차에 다시 틀렸다 → 아직 불안정한 명령.
- **"베이스 박자를 50%만 당겨줘"**: gpt-5.4-mini가 스윙 50%(= 변화 없음)로 읽었다. "박자를 당긴다"는 격자 쪽으로 당기는 것(퀀타이즈)이라는 용어 규칙을 넣고 맞았다.
- **같은 모델도 회차마다 결과가 달라진다** (gpt-6-luna 30 → 29). 한 번 돌린 숫자는 믿기 어려워서, 모델마다 3번 이상 돌려 평균 · 범위로 보고하는 게 다음 할 일이다.
- 정확도는 두 모델이 비슷하고 gpt-5.4-mini가 1초쯤 빠르다. 하지만 **비용은 gpt-6-luna가 훨씬 싸다** (아래 표). 그래서 기본 모델은 gpt-6-luna로 둔다.

## 이어지는 대화 · 스스로 고치기 (39개로 확장)

한 명령만 보는 30개로는 에이전트다운 부분(맥락 기억 · 오류 수습)을 잴 수 없어서 9개를 더했다 ([backend/eval/conversations.py](../backend/eval/conversations.py)). 실제 서버와 같은 코드(`app/agent/session.py`)로 여러 턴을 돌리고, 정답으로 가는 길이 여러 개라 **마지막 상태**로 채점한다.

| | 예 | 확인하는 것 |
| --- | --- | --- |
| 이어지는 대화 6개 | "베이스 2키 올려줘" → 적용 → "한 키 더", "패드 한 옥타브 올려줘" → "아니 내려줘", "하이햇 좀 약하게" → 취소 → "그럼 스네어를 20만큼 세게" | 앞 대화 · 적용 · 취소를 기억하는지 |
| 스스로 고치기 3개 | "베이스 30반음 올려줘"(한 번에 최대 24), "리드를 4옥타브 올려줘"(MIDI 범위 밖), "20마디부터 베이스 약하게"(곡은 16마디) | 도구 오류를 보고 나눠 하거나, 안 되면 바꾸지 않고 설명하는지 |

### 처음 돌렸을 때 드러난 약점 → 고친 것

| 명령 | 처음 | 원인 | 고친 것 |
| --- | --- | --- | --- |
| "패드 한 옥타브 올려줘 → 아니 내려줘" | 0/3 (+1 위에 −1 → 원래대로) | 미리보기에 계속 쌓기만 하고 "버리고 다시"가 없었다 | `start_over` 도구: 이번 명령의 편집과 미리보기를 버리고 현재 버전에서 다시 |
| "베이스 30반음 올려줘" | 0/3 (24만 올리고 끝) | 오류 메시지가 "나눠서 하면 된다"를 알려 주지 않았다 | 범위 오류에 "나눠서 같은 결과를 낼 수 있으면 나눠 부르고, 아니면 바꾸지 말고 알려 줘" |
| "리드를 4옥타브 올려줘" | 0/3 (말없이 3옥타브로 바꿈) | 다른 값으로 바꿔 넣지 말라는 규칙이 없었고, 나눠 하다 중간에 실패하면 반쯤 바뀐 채로 남았다 | "다른 값으로 바꾸지 말고 되묻기" 규칙, 2옥타브 이상은 음역 + 반음이 127을 넘는지 먼저 확인, 중간에 실패하면 `start_over`로 되돌리기 |

규칙을 하나 넣을 때마다 다른 데가 흔들렸다. "옮기기 전에 음역 확인" 규칙을 모든 조옮김에 걸었더니 gpt-5.4-mini가 겁을 먹어 "건반 5반음"에서 정보만 보고 멈추고, 드럼 소리 고르기(pitches)를 빼먹어 37.3 → 32.7로 떨어졌다. 확인은 2옥타브 이상일 때만, 드럼 소리 하나를 말하면 pitches를 꼭 넣으라는 문장을 강조해 되돌렸다. **작은 모델일수록 규칙 문장 하나에 크게 흔들린다.**

채점 수정: "전부 16분음표로 퀀타이즈"를 멜로디 트랙과 드럼으로 나눠 두 번 부른 것도 결과가 같아 정답으로 추가했다(그 전에는 오답 처리). 저장된 결과를 API 호출 없이 다시 채점했다.

## 템포 도구 추가 (42개)

"템포 100으로 바꿔줘"가 안 됐다 — 음표를 고치는 도구만 있었기 때문. `set_tempo`(set · offset · scale, 20~300 BPM)를 추가했다. 음표는 박 단위로 저장해서 템포만 바꾸면 마디 위치는 그대로다. 음표가 하나도 안 바뀌어도 미리보기 · 버전이 생기도록 "바뀐 음 수"만 보던 판정을 "곡 설정이 바뀜(changed_settings)"까지 넓혔다.

## 마디 범위가 다른 편집에 번지는 문제 (43개)

| --- | --- | --- |
| gpt-6-luna | 42 · 43 · 43 | **42.7/43** |

## 악기 바꾸기 (48개)

"악기를 바꿀 수 있나?"라는 요청으로 `set_instrument`(트랙 · General MIDI 번호 0~127)를 추가했다. 음은 그대로고 악기 번호만 바뀌며, 내보낸 MIDI에도 그 번호가 들어간다. 드럼 트랙은 음 번호가 곧 드럼 소리라 건너뛴다. 프롬프트에 자주 쓰는 악기 번호 약 50개를 한국어 이름으로 넣고, "신스로"처럼 종류만 말하면 트랙 역할에 맞춰 고르게 했다.
