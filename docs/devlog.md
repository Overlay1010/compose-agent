# 개발 기록

## v0.1-1 · MIDI 업로드와 트랙 보기

- **문제**: FL Studio는 드럼을 10번 채널로 보내지 않는 경우가 많아 MIDI의 is_drum 값만으로는 드럼 트랙을 찾을 수 없다.
- **시도**: 트랙 이름에 drum, kick, snare, hat, fpc 등이 들어 있으면 드럼으로 판단하도록 보완.
- **결과**: 이름만 Drums인 테스트 트랙도 드럼으로 인식됨 (tests/test_convert.py).

- **문제**: 시간을 초 단위로 다루면 템포가 바뀌는 곡에서 마디 위치가 어긋난다.
- **시도**: 초 → 틱 → 박으로 변환해 내부 시간 단위를 박으로 통일.
- **결과**: 3마디에서 템포가 100 → 140으로 바뀌는 파일에서도 음표의 박 위치가 그대로 유지됨.

## v0.1-2 · 브라우저 재생 (Tone.js)

- **문제**: 퀀타이즈·스윙·세기 조절 같은 편집은 피아노롤로는 차이가 거의 안 보여서, 소리 없이 편집 도구를 만들면 결과를 확인할 방법이 없다.
- **시도**: 원래 계획보다 재생을 앞당겨 편집 도구 전에 구현. 시간은 백엔드와 같은 박 단위로 두고 Tone.js Transport의 틱(1박 = PPQ틱)으로 바꿔 예약. 악기는 `Voice` 인터페이스로 감싸서 나중에 사운드폰트로 바꿀 때 그 부분만 교체하게 함.
- **결과**: 재생·정지, 재생선, 트랙 음소거, 스페이스바 단축키 동작. 100 BPM 데모에서 재생선 속도 1.68박/초 (계산값 1.67).

- **문제**: FL Studio 파일은 악기 번호가 전부 0인 경우가 많아 악기 번호만으로는 베이스·패드를 구분할 수 없다.
- **시도**: 트랙 이름(bass, 808, pad, lead 등)도 같이 보고 소리를 고름. 드럼은 General MIDI 번호(36 킥, 38 스네어, 42 하이햇 …) 기준.
- **결과**: 데모 파일에서는 정상. FPC의 실제 음 배치는 FL Studio에서 내보낸 파일로 확인 필요.

- **문제**: 재생 중 가끔 `Start time must be strictly greater than previous start time` 오류가 나며 킥이 한 번 빠짐.
- **시도**: 킥이 불릴 때의 시각을 로그로 찍어 보니, Transport가 같은 틱(4박)의 이벤트를 부동소수 오차만큼 다른 시각(2.5107초)으로 **두 번** 부르고 있었다. 드럼의 "같은 시각이면 건너뛰기" 비교가 정확히 같은 값만 걸러서 놓친 것.
- **결과**: 예약 단계에서 같은 이벤트가 1ms 안에 다시 불리면 무시하도록 감쌈 (멜로디 음이 두 번 겹쳐 커지는 것도 같이 막음). 자동 브라우저 테스트 3회 반복에서 오류 0건.

## v0.1-3 · 샘플 보강, 808 판정, 드럼 레인

- **문제**: 샘플이 4마디·트랙 3개(킥·스네어만)뿐이라 소리 확인도, 앞으로 만들 편집 도구 시험도 어렵다.
- **시도**: `scripts/make_samples.py`로 용도별 샘플 4개를 코드로 생성 (메인 데모 16마디 5트랙, FL Studio식 흔들린 파일, 3/4 박자, 템포 변화). 음표를 직접 써서 저작권 문제 없음, 고정 시드라 다시 만들어도 같은 파일.
- **결과**: 샘플이 제대로 읽히는지 `tests/test_samples.py`로 고정. 흔들린 파일은 16분음표 격자를 벗어난 음이 80% 이상이어서 나중에 퀀타이즈 도구 시험에 그대로 쓸 수 있다.

- **문제**: 드럼 판정 키워드에 `808`이 있어서 FL Studio에서 흔한 "808 Bass" 트랙이 드럼으로 잡힌다.
- **시도**: "이름에 bass가 있으면 드럼 아님" 규칙도 생각했지만 "Bass Drum"(= 킥)을 틀리게 된다. 대신 `808`을 키워드에서 뺐다. 808 킥·스네어는 보통 "808 Kick"처럼 kick/snare가 같이 붙어서 그대로 드럼으로 잡힌다.
- **결과**: "808", "808 Bass"는 멜로디, "808 Kick", "Bass Drum", "FPC"는 드럼 (`test_looks_like_drum`).

- **문제**: 드럼 트랙도 피아노롤에 C2, C3 같은 음 이름으로 나와서 어떤 소리인지 읽기 어렵다.
- **시도**: DAW 드럼 에디터처럼, 트랙에서 쓰인 음만 레인으로 보여 주고 GM 이름(Kick, Snare, Closed Hat …)을 붙임. 레인 높이도 두 배로.
- **결과**: lofi_groove 드럼이 Kick~High Tom 10개 레인으로, FPC 트랙은 쓰인 3개(Kick · Clap · Closed Hat)만 보인다. GM 목록에 없는 음은 음 이름으로 표시 (FL Studio FPC 배치 확인 후 필요하면 이름 추가).

## v0.1-4 · 편집 도구 6개

- **문제**: 나중에 LLM이 도구를 고르고 인자를 채우는데, 인자가 틀리거나(semitones=100, 오타 난 인자 이름) 없는 트랙을 가리키면 엉뚱한 편집이 조용히 적용될 수 있다.
- **시도**: 도구마다 pydantic 인자 모델을 두고 `run_tool`이 먼저 검증. 범위는 `Field`로, 모드별 범위(세기 set은 1~127 등)는 검증 함수로. 모르는 인자는 `extra="forbid"`로 거부. 오류 메시지에는 틀린 인자 이름과, 없는 트랙이면 쓸 수 있는 `id(이름)` 목록을 넣어 LLM이 다시 시도할 수 있게 함. 같은 인자 모델에서 JSON Schema(`tool_specs()`)를 뽑으니 설명과 검증이 어긋나지 않는다.
- **결과**: 잘못된 인자 11가지가 모두 `invalid_args`로 막히고, 메시지에 해당 인자 이름이 들어 있음 (`test_run_tool_rejects_bad_args`).

- **문제**: "전체 반음 올려줘"에 드럼까지 옮기면 드럼은 음 번호가 곧 악기라서 킥(36)이 37(사이드 스틱)로 바뀌어 버린다.
- **시도**: transpose · shift_octave는 드럼 트랙을 항상 건너뜀. 사용자가 드럼 트랙을 직접 골랐을 때만 요약에 "건너뛰었어요"를 붙인다 (전체를 고른 경우엔 당연해서 생략).
- **결과**: 범위를 벗어나는 음이 하나라도 있으면 아무것도 바꾸지 않고 오류. 메시지에 "이 선택은 -60~+7반음 사이로만"처럼 가능한 범위를 같이 알려 준다.

- **문제**: 스윙은 "뒷박에 있는 음만" 늦춰야 하는데, 박 위치가 부동소수라 정확히 0.5와 같은지로는 못 찾는다.
- **시도**: 격자 번호 k = round(시작 / 격자)가 홀수이고 실제 위치가 k × 격자에서 0.02박 안이면 뒷박으로 봄. 늦추는 양은 DAW 방식 (percent/100 × 2 − 1) × 격자 (60% 8분음표 = 0.1박). 음을 정확한 위치로 옮기지 않고 현재 위치에서 늦추기만 해서, 이미 스윙된 음은 허용 범위를 벗어나 두 번 늦춰지지 않는다.
- **결과**: lofi_groove에서 하이햇(42)만 골라 60%를 주면 뒷박 하이햇만 0.1박 늦춰지고 앞박 하이햇 · 킥 · 스네어는 그대로. 50%는 변화 0. 타이밍이 흔들린 fl_style_loose는 0.02박 안에 드는 음만 움직여서, 뒷박을 못 찾으면 요약에서 퀀타이즈를 먼저 권한다.

- **문제**: 퀀타이즈 · 세기 계산에서 파이썬 `round`는 0.5를 짝수 쪽으로 보내(round(0.5) = 0, round(1.5) = 2) 같은 거리의 음이 위치마다 다르게 붙는다.
- **시도**: `floor(x + 0.5)`로 항상 올림. 셋잇단 격자(1/3, 1/6)는 JSON으로 정확히 못 쓰므로 0.01 안에 가까운 값(0.3333)이면 받아 준다. 끝까지 맞출 때(`quantize_ends`) 짧은 음이 시작과 같은 칸으로 붙으면 길이 0 대신 한 칸 길이로.
- **결과**: 강도 100%면 fl_style_loose 전체가 16분음표 격자에 맞고 길이는 그대로, 50%면 격자까지 거리가 절반이 된다.

## v0.1-5 · 실제 악기 샘플로 재생

- **문제**: Tone.js 기본 신스 소리는 음·리듬 확인은 되지만 시연용으로는 너무 빈약하다.
- **시도**: 무료 샘플을 라이선스부터 확인. 멜로디는 FluidR3 GM(CC BY 3.0, 악기 128개)을 악기 번호로 불러오고, 드럼은 Sonic Pi 샘플(CC0)을 레포에 넣음. 라이선스 표기가 없는 샘플(Tone.js 드럼 등)은 레포가 공개라 쓰지 않았다. 고음질 피아노(Splendid Grand, 퍼블릭 도메인)는 주소가 바뀌어 불러오지 못해 다음으로 미룸.
- **결과**: 트랙 음역에서 3반음마다 하나씩만 불러와 lofi_groove 기준 샘플 35개, 첫 재생 전 로딩 약 0.4초. 실제 하이햇처럼 닫힌 하이햇이 열린 하이햇 소리를 끊는다.

- **문제**: FL Studio 파일은 악기 번호가 전부 0이라 모든 트랙이 피아노 소리가 된다.
- **시도**: 악기 번호가 0이면 트랙 이름으로 고름 (bass → 핑거 베이스, 808 → 신스 베이스, rhodes/keys → 전자피아노, pad → 따뜻한 패드 …).
- **결과**: fl_style_loose의 Bass 트랙이 피아노가 아니라 베이스 소리로 나온다.

- **문제**: 샘플 서버에 못 닿으면(오프라인 시연 등) 소리가 아예 안 날 수 있다.
- **시도**: 로딩이 실패하거나 15초가 넘으면 그 트랙만 예전 신스로 바꾸고 화면에 안내. 로딩 중에 정지를 누르면 로딩이 끝나도 재생하지 않게 함.
- **결과**: 어떤 경우에도 재생은 된다.

## v0.1-6 · LLM 에이전트 연결

- **문제**: "하이햇 약하게 하고 스윙도"처럼 한 문장에 편집이 여럿이고, LLM이 트랙 id를 틀릴 수도 있다. 그렇다고 에이전트가 마음대로 곡을 바꾸면 안 된다.
- **시도**: 도구를 부르고 결과를 돌려주기를 답이 나올 때까지 반복하는 루프 (최대 6번). 편집은 작업용 사본에만 쌓이고 사용자가 "적용"해야 버전이 된다. 도구 오류는 예외로 끝내지 않고 메시지를 LLM에 돌려줘서 스스로 고치게 함. 현재 트랙 목록과 드럼에 쓰인 소리(42 Closed Hat …)를 시스템 프롬프트에 넣어 조회 왕복을 줄임.
- **결과**: 실제 모델로 명령 7개 시험: 조옮김 · 마디 범위 · "코드" → Chords 트랙 · 하이햇만 골라 세기+스윙 두 단계 모두 맞음, 명령당 3~4초. 잘못된 트랙 id → 오류 메시지 보고 재시도하는 흐름은 테스트로 고정 (FakeLLM).

- **문제**: "좀 더 좋게 해줘" 같은 막연한 요청에 묻지도 않고 전 트랙에 스윙을 넣고 세기를 줄였다.
- **시도**: 프롬프트에 "막연한 요청은 네 취향으로 편집하지 말고, 할 수 있는 편집 2~3개를 제안하며 되물어"를 넣음.
- **결과**: "좀 더 좋게 해줘", "느낌 있게 바꿔줘" 둘 다 편집 없이 선택지를 제안하는 답으로 바뀜. 평가셋에 막연한 요청도 넣어서 계속 확인할 것.

- **문제**: 사용한 모델이 Chat Completions에서 도구를 쓰려면 `reasoning_effort`를 꼭 `'none'`으로 지정해야 한다며 400 오류.
- **시도**: 그 오류일 때만 한 번 `'none'`으로 바꿔 다시 부르고 이후에도 유지. 모델마다 다른 제약을 LLM 연결 코드 한 곳에서 흡수.
- **결과**: 모델을 바꿔도 에이전트 코드는 그대로.

- **문제**: 미리보기가 있는 동안 다음 명령("멜로디도 내려줘")을 보내면 어디서부터 편집할지.
- **시도**: 적용 전까지는 미리보기 위에 이어서 쌓고, 적용하면 그동안의 편집이 한 버전이 된다. 되돌리기는 기록을 지우지 않고 예전 상태를 새 버전으로 올림.
- **결과**: 버전 기록에 "Bass 트랙 61개 음을 2반음 올렸어요. · Lead 트랙 47개 음을 1옥타브 내렸어요."처럼 한 줄로 남는다.


## v0.1-7 · FL Studio만이 아니라 모든 DAW

- **문제**: 드럼을 10번 채널과 트랙 이름으로만 찾고 있었는데, DAW마다 내보내는 방식이 다르다. Ableton은 `Kit-Core 909`, Cubase는 `Groove Agent SE`, Logic Drummer는 트랙 이름이 드러머 이름(`SoCal (Kyle)`)이라 이름 규칙으로는 못 찾는다.
- **시도**: 이름 키워드를 DAW별로 늘리고(짧은 단어 `hat` · `tom` · `kit`은 "Custom", "Toolkit"에 걸리지 않게 단어 단위로), 이름이 없어도 찾을 수 있게 **음 패턴 판정**을 추가. GM 드럼 번호 범위 + 킥 · 스네어 · 하이햇 중 2가지 이상 + 짧은 음 + 여러 소리가 같은 순간에 겹침.
- **결과 1**: 처음 기준으로는 샘플팩 멜로디 루프 37개 중 **4개를 드럼으로 잘못 판정**. 낮은 음역 코드가 GM 번호와 겹치고 코드라서 "같이 침"도 통과했다. 실제 드럼과 숫자를 비교해 보니 드럼은 59(B3) 위 음이 거의 없고 음의 90% 이상이 상위 3개 소리에 몰려 있었다(멜로디 루프는 46~65%). 이 두 조건을 추가해 **잘못 판정 0개**.
- **결과 2**: 사람이 친 드럼은 킥과 하이햇 시작이 정확히 같지 않아서 "같이 침"을 같은 틱이 아니라 0.1박 안으로 넓혔다. 이름 없이도 흔들린 FPC 트랙을 드럼으로 찾는다. 킥과 하이햇이 한 번도 겹치지 않는 아주 단순한 패턴은 여전히 이름(`Drums`)으로만 찾는다.

## v0.1-8 · 채팅 화면으로 MVP 흐름 완성

- **문제**: 백엔드는 미리보기 → 적용 흐름이 다 있는데 화면에서는 쓸 수 없었다. 무엇이 바뀌는지 보이지 않으면 "적용"을 누를 근거가 없다.
- **시도**: 채팅 패널(실행한 도구를 단계별로 표시), 피아노롤에 바뀔 음(라임)과 원래 위치(점선), 바뀐 소리 / 원래 소리 전환, 적용 · 취소 · 되돌리기, 버전 기록 패널을 차례로 붙였다(단계마다 커밋).

## v0.1-22 · 한글 트랙 이름이면 .mid 대신 .txt가 받아지던 문제

- **문제**: ".mid 내보내기"를 누르면 .txt 파일이 받아졌다. 서버가 500을 냈고, 브라우저가 오류 문구("Internal Server Error")를 그대로 파일로 저장한 것. 원인은 에이전트가 만든 "탑노트" 같은 한글 트랙 이름 — MIDI 트랙 이름은 바이트 문자열이고 mido는 latin-1로만 쓰기 때문에 `UnicodeEncodeError`.
- **시도**: 트랙 이름을 UTF-8 바이트로 넣고(요즘 DAW는 UTF-8로 읽는다), 불러올 때 UTF-8로 풀리면 되돌린다(원래 latin-1 이름은 그대로). 내보내기 버튼은 링크 대신 먼저 내려받아 확인하고, 실패하면 파일 대신 화면에 오류를 띄운다.
- **결과**: 사용자 프로젝트를 브라우저에서 내보내 `MThd`로 시작하는 .mid 확인, 다시 읽으면 "탑노트" 이름 그대로. 한글 · latin-1 이름 왕복 테스트 추가. 그동안 테스트는 영어 트랙 이름만 써서 못 잡았다.

## v0.1-23 · 트랙별 MIDI · 음원 내보내기

- **문제**: 내보내기가 모든 트랙이 든 .mid 하나뿐이었다. DAW에 트랙별로 끌어다 놓거나, 들어 본 소리를 그대로 음원으로 공유할 방법이 없었다.
- **시도**: 내보내기 버튼을 메뉴로 바꿨다 — MIDI(전체 곡 · 트랙별 .zip · 트랙 하나), 음원(WAV · MP3 · FLAC · OGG · M4A · MP4). 트랙 하나짜리 .mid에도 템포 · 박자 · 악기 · 볼륨 · 팬을 넣어 DAW에서 위치가 맞게 했다. 음원은 재생과 똑같은 악기 · 드럼 킷 · 효과로 브라우저에서 오프라인 녹음(Tone.Offline)해 WAV를 만들고, 다른 형식은 서버가 ffmpeg로 바꾼다(MP3 320k, AAC 256k). ffmpeg가 없으면 WAV만 보여 준다.
- **결과**: 브라우저에서 WAV · MP3 · MP4를 받아 ffprobe로 확인 — 44.1kHz 스테레오, 48.2초(16마디 84 BPM 45.7초 + 울림 2.5초), 평균 -24dB · 최고 -2dB로 깨짐 없음. 처음엔 "다른 오디오 컨텍스트의 노드에 연결할 수 없다" 오류가 났다: Tone.Offline은 녹음을 시작하자마자 전역 context를 원래대로 돌리는데, 드럼은 소리마다 재생 노드를 전역 기본값으로 새로 만들고 있었다 → 드럼 버스와 같은 context로 만들게 고쳤다.

## v0.1-24 · "버전 기록" → "히스토리"

- **문제**: "버전 기록 v3", "v2로 적용했어요", "v1 상태로 되돌렸어요 (v4로 저장)"처럼 개발자식 버전 번호가 화면 곳곳에 있어 곡 작업하는 사람에게 와닿지 않았다.
- **시도**: DAW 사용자에게 익숙한 "히스토리"로 이름을 바꾸고, 번호 대신 무엇을 했는지 · 언제 했는지로 보여 준다 (저장마다 시각을 남김, 예전 저장 파일에는 칸을 자동으로 추가). 알림은 "적용했어요", "'원본 업로드' 상태로 되돌렸어요", "바로 전 상태로 되돌렸어요"로, 상단은 "저장됨 · 3분 전"으로. 화면에서 바꾼 악기 · 볼륨 기록도 도구 요약(영어 악기 이름) 대신 화면 알림과 같은 문장으로 남긴다. 파일 이름의 `_v3`는 내려받은 파일을 구분하는 데 쓸모 있어 그대로 둔다.
- **결과**: 브라우저에서 악기 바꾸기 → 말로 편집 → 적용 → 히스토리(번호 · 설명 · "방금" · "지금") → "원본 업로드"로 되돌리기까지 새 문구로 확인. 시각 칸이 없던 예전 저장 파일을 여는 테스트 추가.

## v0.1-25 · 화면에서 고른 부분을 말로 고치기

- **문제**: 범위를 말하려면 "9마디부터 12마디까지"처럼 숫자로 말해야 했다. 피아노롤을 보면서 "여기"라고 하고 싶은데 에이전트가 어디인지 몰랐다.
- **시도**: 피아노롤에서 끌면 그 트랙의 시간 구간(16분음표 단위, 드럼은 끈 레인까지), 전체 구성에서 끌면 모든 트랙의 그 마디(구간 반복도 같이)를 고른다. 멜로디는 음높이를 고르지 않는다 — "올려줘 → 아니 내려줘"처럼 이어 말해도 같은 부분을 가리키게. 고른 부분은 입력칸 위 칩으로 보이고 ✕ · Esc · 빈 곳 클릭으로 푼다. 메시지와 함께 보내 시스템 프롬프트에 적고, 마디 중간부터 고를 수 있게 도구 선택 조건에 박 범위(beats)를 더했다.
- **결과**: 브라우저에서 Rhodes 5~6마디를 끌어 "여기 한 옥타브 올려줘" → `beats [16, 24]`로 그 안의 음 8개만 바뀜, 전체 구성 끌기 → "모든 트랙 · 9~12마디", 드럼 Closed Hat 레인만 끌기 → "Drums Closed Hat · 1~2마디". 평가 중 빈 track_ids 버그도 찾아 고쳤다.

## v0.1-26 · Claude로 바꾸기

- **문제**: 에이전트가 OpenAI Chat Completions에만 묶여 있었다. 사용자가 OpenAI 대신 Claude를 쓰기로 했다.
- **시도**: 에이전트 루프는 그대로 두고(메시지는 계속 OpenAI 형식으로 쌓음) `AnthropicChat`이 Claude Messages API 형식으로 바꿔 보낸다 — system은 따로, tool_calls → tool_use 블록, tool 결과 → 사용자 쪽 tool_result 블록, 대화 중간의 적용 · 취소 알림은 사용자 쪽 알림 글로. 명령마다 같은 도구 설명 · 규칙(약 19,000토큰)에 프롬프트 캐시를 건다(도구 목록 끝 · 규칙 블록 · 마지막 메시지). `.env`의 `LLM_PROVIDER`로 Claude ↔ OpenAI 형식(OpenAI · Ollama · Gemini)을 고르고, 평가는 모델 이름(`claude-…`)으로 고른다.
- **결과**: 변환 · 캐시 위치 · 키 없을 때 안내를 가짜 클라이언트로 테스트(229개 통과). 실제 Claude 평가는 API 키를 넣은 뒤 돌린다.
