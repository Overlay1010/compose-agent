# 로드맵

모든 기능은 "에이전트가 고르는 도구"로 하나씩 늘어난다. 뼈대(채팅 → 도구 → 미리보기 → 적용)는 v0.1에서 완성하고, 그 위에 도구만 더한다.

원칙: **계산은 검증된 코드나 라이브러리가, LLM은 도구 선택과 설명만.** 그래야 결과를 테스트하고 숫자로 평가할 수 있다.

화면 구상(프로토타입): Claude 아티팩트 "Compose Agent 완성본 목업"의 "완성본 (v1.0) 구상" 줄.

음악 전공자로서의 차별점. 다음 단계(말로 만들기)가 코드 진행을 기준으로 음을 만들기 때문에 먼저 한다.

- [x] `analyze_harmony` 도구: "무슨 키야? · 9~12마디 코드 뭐야? · 여기 코드 뭐야?"에 분석 결과로 답함 (평가 6개)
- [x] 평가: 정답을 아는 생성 진행 576곡(코드 7화음 97% · 조성 570/576) · Cymatics 37곡 조성(25/37). **LLM 단독 vs LLM + 분석 엔진** — 엔진만이 가장 정확 (eval.md)
- [x] 입력 토큰 줄이기: 도구 인자 스키마 군더더기 · 반복 설명 덜기 → 명령당 입력 −18%, 85/85 그대로. 분야별로 나눠 보내기는 프롬프트 캐시가 깨져 오히려 비싸서 하지 않음 (eval.md)
- [x] 대리코드 · 리하모니 제안 `suggest_reharmonization`. 제안마다 그 마디 멜로디 음과 부딪히는지 코드로 검사
  - 대리 종류(모두 규칙으로 계산): 같은 기능 바꾸기(IV ↔ ii, 단조 iv ↔ iiø) · 텐션 더하기(음계 안의 7 · 9음) · 부속 딸림 · ii–V 끼워 넣기 · 트라이톤 대리(V7 → bII7) · 빌려온 화음(장조 iv · iiø · bVII7, 없으면 bVI / 단조 IV7 · ii · V7 · 끝 I)
  - 색깔이 다른 진행 3개(가볍게 · 재지하게 · 색다르게). 스타일마다 코드별 후보를 앞에서부터 시도해 부딪히지 않는 첫 후보를 쓴다 (LLM은 설명만). 바꿀 게 없는 스타일은 빠진다
  - 센 부딪힘만 뺀다: 센박이거나 한 박 넘게 울리는 멜로디 음이 새 코드 음의 반음 위(b9)면 그 바꾸기를 버리고 다음 후보로, 약박의 짧은 음은 "살짝 부딪혀요"로 표시. 딸림7의 b9 · b13과 원래도 부딪히던 음은 세지 않음
  - 화면: 채팅에 제안 카드, 누르면 코드 띠가 그 제안을 보여 주고 바뀌는 코드만 라임색 (다시 누르면 원래대로). "이걸로 바꾸기"는 `apply_chords`와 함께
  - 평가: 리하모니 명령 4개(R01~R04, 이전 A06 "아직 못 함"을 바꿈) · 엔진 테스트 10개
- [x] 제안한 코드로 건반 · 패드 · 베이스 바꾸기 `apply_chords` (미리보기로). 제안을 같은 범위로 다시 계산해 그대로 바꾼다 (LLM이 코드 목록을 옮겨 적지 않음)
  - 건반 · 패드: 같이 친 음 묶음(0.1박 안)마다 음 개수만큼 중요한 코드 음(3 · 변한 5 · 7음 → 텐션 → 5음 · 근음)을 골라 덜 움직이게 짝짓기 — 베이스가 근음을 치니 건반은 근음 없는 보이싱(Cmaj9 = E B D)
  - 베이스: 근음 차이만큼 가까운 쪽으로 통째로 옮기고, 코드 음(3 · 5 · 7음)은 새 코드의 같은 자리로(Dm9 → Dm7b5의 5음 A → Ab). 근음이 바뀌면 첫 음은 새 근음. 베이스 트랙이 없으면 음마다 베이스인지 본다
  - 리듬 · 세기 그대로, 멜로디 · 드럼 그대로, 음을 더하지 않음 (음이 적은 트랙은 9 · 13음이 다 안 들어감)
  - 카드의 "이걸로 바꾸기" = 같은 범위로 "○○ 제안으로 코드 바꿔줘"
  - 확인: 바꾼 곡을 분석 엔진으로 다시 읽으면 제안과 같은 코드 — 샘플 곡 98% · 샘플팩 37곡 이름 75% / 구성음 93% (eval.md)

## v0.3 · 말로 만들기

"로파이 드럼 8마디 깔아줘", "이 코드에 베이스라인 만들어줘", "C – Am – F – G로 피아노 반주"처럼 설명만으로 새 트랙을 만든다.

LLM이 음표를 직접 하나하나 쓰게 하면 긴 곡에서 박자 · 음정이 쉽게 틀린다. 그래서 **음악 규칙으로 만드는 생성기(도구)**를 두고, LLM은 그 생성기의 설정(스타일 · 마디 수 · 밀도 · 스윙 · 음역)만 고른다.

- 드럼 패턴: 장르별 기본 패턴(로파이 · 붐뱁 · 하우스 · 트랩 …) + 밀도 · 필인 · 스윙 · 사람 느낌(세기 · 타이밍 흔들림)
- [x] **첫 작업 · 패드 깔기** `generate_chords(pattern="pad")`: "패드 하나 더 깔아줘" → 곡의 코드(v0.2 분석)를 읽어 새 트랙에 코드마다 4음을 길게 깐다 (2026-10-29 사용해 보고 나온 요청, 2026-10-30 완료)
  - 음역: 베이스 위쪽 · 멜로디 아래쪽 사이 빈 곳, 좁으면 멜로디 바로 아래 한 옥타브. 말로 낮게 · 높게
  - 음 잇기: 목소리마다 코드 음 후보 중 겹치지 않고 음역 안이며 3 · 7음을 다 넣는 조합 중 가장 덜 움직이는 것, 반음으로 붙은 두 음은 피함
  - 소리: 곡 편성에 맞춰 (스트링 · 관악기 → 스트링 앙상블, 신스 · 일렉트로닉 킷 → 폴리신스 패드, 그 밖 → 따뜻한 패드, 이미 있으면 다른 패드). 템포로는 고르지 않음
  - 트랙을 말하면("Rhodes를 패드로 겹쳐줘") 지금처럼 트랙 복제
- [x] **v0.2에서 넘어온 것** (바꾼 곡 다시 읽기에서 이름이 다른 박 25%의 원인, 샘플팩 37곡 · 2026-10-30 완료 — 다시 읽기 이름 75 → 84%)
  - 텐션 음 하나 더하기 (17% → 10%): 화음 묶음에 3 · 7음이나 9 · 13음이 빠지면 같은 박 · 길이 · 세기로 한 음까지 더한다. 묶음이 흩어진 트랙은 구간 첫 묶음에. 남은 건 대부분 짧은 펼침화음뿐인 트랙
  - 한 트랙에 섞인 선율을 엔진이 알아보기: 화음 위 5도 넘게 떨어져 짧게 지나가는 음은 9 · 11 · 13음으로 이름에 붙이지 않는다 (근음 · 3화음에는 그대로 센다). 생성 곡 576곡 · 샘플팩 조성 그대로
  - 같은 음 · 다른 이름 정하기 (2% → 1%): 6음이 베이스인 m6는 베이스를 근음으로 한 m7b5 (Gm6/E → Em7b5). 남은 건 #/b 표기만 다른 것
- 코드 반주: 진행(직접 말하거나 v0.2 분석 결과) → 보이싱 · 리듬 패턴(길게 · 끊어서 · 아르페지오)
- 베이스라인: 코드 근음 · 5도 · 경과음 규칙, 킥과 맞물리는 리듬
- 멜로디: 코드 톤 중심 + 스케일 경과음, 모양(올라감 · 내려감 · 아치)과 리듬 밀도
- 짧은 모티프(1~2마디)는 LLM이 직접 써도 되지만, 생성기 결과와 같은 검사(음역 · 스케일 · 박자)를 거친다
- [x] **공통 틀** (2026-10-30)
  - 생성 검사 `app/generate/check.py`: 코드 밖 · 음계 밖 · 박 어긋남 · 악기 음역 밖 · 같은 음 겹침. 만들기 도구는 결과에 걸린 것을 적고, 평가는 하나라도 있으면 실패
  - 결과는 다른 편집처럼 **미리보기 → 적용**. 마음에 안 들면 "다른 버전" → 같은 트랙을 version만 올려 다시 (새 트랙을 또 쌓지 않음, 지금과 같게 나오면 다음 버전)
  - 빈 새 트랙 추가 `add_track` (악기 · 드럼 킷 고르기. 악기 바꾸기 · 트랙 복제 · 겹치기는 v0.1에서 먼저 함)
- 도구: `generate_drums` `generate_chords` `generate_bassline` `generate_melody` `add_track`
- 평가: 생성 명령 30개 · 규칙 위반 0개(스케일 밖 음, 박자 밖 음, 음역 초과) · 사람 블라인드 평가(직접 만든 것과 비교)
- 나중 선택지: text-to-MIDI 학습 모델(GPU 필요)을 생성기 하나로 추가해 규칙 기반과 비교

## v0.4 · 멜로디에 편곡 깔기

멜로디 MIDI 하나만 올리고 "어울리는 코드랑 베이스, 드럼 깔아줘"라고 하면 반주 트랙들이 생긴다. v0.2(화성 계산)와 v0.3(생성기)을 합치는 단계라 그 뒤에 한다. 작곡가에게 가장 와닿는 장면이라 **포트폴리오 대표 시연**으로 쓴다.

- 멜로디 화성 붙이기: 조성 찾기 → 마디마다 강박 · 긴 음을 덮는 코드 후보를 규칙으로 계산 → LLM은 "밝게 · 슬프게 · 재즈풍" 같은 요청에 맞춰 후보 중에서 고르고 이유를 설명
- 고른 코드 진행으로 v0.3 생성기를 이어서 실행: 코드 반주 · 베이스 · 드럼 · 대선율(멜로디 3도 아래 · 옥타브 겹치기)
- 한 번에 여러 트랙이 미리보기로 생기고, 트랙마다 "다른 버전"으로 다시 만들 수 있다
- 도구: `harmonize_melody` `arrange` (생성기 여러 개를 순서대로 부르는 묶음)
- 평가: 코드가 붙어 있는 곡의 멜로디만 떼어 넣고, 원래 코드와 얼마나 같은지(화성 기능 기준) · 멜로디와 부딪히는 음 수 · 블라인드 청취 평가
